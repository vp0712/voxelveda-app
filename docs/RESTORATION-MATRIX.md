## Shared-service compatibility that must be repaired explicitly

1. **Permissions:** current `permissionCatalog`, `authorizationService`, input middleware and user-controller updates intentionally removed all business privileges. Merge original capability definitions and record scopes without reverting current MFA/session/security checks. Read access and mutation permission are separate: do not require input/edit capability just to list a customer/compliance record.
2. **Mail:** current `emailService`, `emailQueue` and job store permit only account/security/contact mail and no attachments. Original invoice, timesheet, roster and careers workflows need an explicit module allowlist and PDF-only attachment validation. Retired queue rows remain untouched and unclaimed. Do not downgrade to an earlier SMTP implementation.
3. **Documents:** `applicationRetirement.documentModuleAvailable` currently allows only `profile`/`security`. Expand it for confirmed original records while keeping Finance and ERP files unavailable. Keep existing storage, malware, record ownership, restricted-file step-up and download-grant protections.
4. **Jobs:** restore only original weekly timesheet/approval notification tasks using current distributed job coordination. Retain inactive Banking sync/statement ingestion and excluded module cleanup. Never enable production destructive purge as an incidental restoration step.
5. **Procurement:** extracting `dateOnly` does not require loading `financeSchema` or `financeRoutes`. The latest purchase workspace also contains Finance bill matches; isolate these rather than mounting retired supplier-payment APIs. Keep original PO/receipt quantities and approval authority operational.
6. **Audit:** preserve existing audit entries and integrity chains. Business detail histories need restored module-specific visibility; account security views need not expose excluded Finance/ERP metadata. Do not rewrite historic audit module values to make them appear retained.
7. **Startup/schema:** retain the current public readiness/startup gateway, database availability protection, HTTPS canonical host, current domain, migration checksums/ledger and existing record IDs. Inspect live schema before adding columns; legacy create-if-missing helpers are not evidence that all migrations can be replayed safely.
8. **Theme/navigation:** original admin/staff markup contains both original business sections and added Finance/ERP navigation. Restore only the former under shared navy/blue tokens. Keep the current original logo bytes. Remove retired references from quick links, notification actions, role portals and cached/service-worker assets.

## Decisions and validation limits

History resolves the original/main-app versus added ERP portal boundary without a user clarification: the earlier ERP-labelled procurement/approval/archive commits integrated business workflows into the original app; the later `erpWorkspace*` commits created the separately added portal. Recruitment and QMS are independently mounted business workflows, not dependencies of that portal.

The matrix does not authorize invented quotations/orders, new Finance ledgers, fabricated dashboard records, production data deletion, credential changes, provider changes, billing purchases or DNS changes. It records the minimum end-to-end dependencies that need restoration and verification. Actual tests, schema inspection, PDF rendering/MIME checks, recipient limitations and deployed commit evidence must be reported separately by the release work.
