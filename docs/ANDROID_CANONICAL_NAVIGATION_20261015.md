## Evidence and diagnosis

The source architecture is Capacitor 8.5.2 `BridgeActivity` / Android WebView. It is not a TWA implementation. Historical `capacitor.config.json` immediately before `ae011107` contains `server.url=https://voxelveda-app-production.up.railway.app` and `cleartext:true`. That commit changed source to the canonical URL, but no complete Android Gradle project, generated release artifacts, native signing workflow or Play upload workflow was retained. Only MainActivity and AndroidManifest were tracked. Changing hosted files cannot update a previously installed binary's bundled server URL.

The locked Capacitor Bridge's `launchIntent` creates an Android `ACTION_VIEW` when a navigation host/scheme differs from its configured app URL and is not in its allow-navigation mask. The old host and canonical host are different. This is the concrete framework mechanism under test, including an actual native framework baseline dispatch assertion. Current login/MFA use relative first-party navigation; no external OAuth provider is configured in the retained application. Domain association concerns OS HTTPS app links; ordinary WebView navigation does not require TWA verification.

Production observations before repair: canonical `/api/ready` is healthy at the starting commit; the old Railway `/login` returns HTTP200 and serves login on the infrastructure host; canonical `/.well-known/assetlinks.json` returns an HTML404. Production public variable values are redacted; their names do not establish values. Source also allowed stale APP_URL/PUBLIC_APP_URL values into email/careers links. Login and MFA return-path filters dropped valid staff, attendance and document paths.

The public Play listing for `com.voxelveda.app` returns200, identifies Voxel Veda and reports an update date of 22 July 2026. Source migration `ae011107` is dated 3 August 2026. The listing therefore predates the source URL migration, supporting an outdated-build explanation without establishing the affected installed binary or Play version code.

The affected phone's installed package/version/channel and Play Console's current release and signing identity are **not available**. No connected device, existing APK/AAB, Play connection or production test account was supplied. GitHub denies signing secret/variable metadata access with HTTP403. Therefore these findings establish the source/framework defects and legacy URL source, without claiming that the particular installed phone has been inspected or that its exact binary matches a source commit.

## Changes

- Restore a complete native project from the locked Capacitor template. Synchronize actual bundled configuration with canonical HTTPS, one exact allowed application host, mixed content disabled and native logging disabled. Bundle only a small branded recovery shell, not stale copies of the operational portals. Original hosted app and identity remain.
- Native navigation never delegates ordinary first-party flows to Capacitor's external fallback. Canonical routes stay in WebView; safe legacy GET links are rewritten to the canonical origin with path/query/fragment preserved. Arbitrary schemes, credentials, ports and hostname lookalikes are rejected. Unsolicited external navigation is blocked; genuine user-initiated external links need an explicit native confirmation. No third-party OAuth provider is introduced or forced into WebView.
- Single-task HTTPS app-link intent filter and cold/warm intent handling preserve the safe route and original cookie/permission checks. Association uses only supplied, syntactically valid public **Play App Signing** certificate SHA256 fingerprints for the unchanged package. Upload-key and test-debug identities are not substituted. Without a verified fingerprint the endpoint returns JSON `[]` with503 and no cache, explicitly providing no association. Never claim OS verification until real signing identity is configured and observed.
- Bounded branded launch/connection recovery, explicit GET retry, normal cookie persistence/flush, safe-area/IME sizing, light/dark status bars, native Back handling for sheets/dialogs/dirty forms and package/version/source information in account settings. No automatic payment, attendance or document-send retry, session-policy relaxation or cookie/token copying across origins.
- Keep actual in-app PDF.js previews. Native PDF view/save uses the same authorised response bytes, safe .pdf filenames, application/pdf and an additional Android PdfRenderer parse. Native viewer is non-exported; user-selected storage confirms successful writes. HTML/failed responses cannot become PDFs. Camera recovery can open the application's permission settings and return to a deliberate Retry action.
- Legacy host GET/HEAD navigation redirects to canonical HTTPS while health/readiness probes remain available. Legacy writes return explicit409 without forwarding credentials, replaying writes or converting POST to GET. Infrastructure, DNS, Railway hosting and mail providers remain. Shared application link generation refuses old infrastructure/public alternative origins, and login/MFA preserve validated retained destinations with original server authorization.
